# orbit — context for AI agents

Personal hub for the user's Hetzner server `your-server`, served at root `/` of `https://your-dashboard.example/` (Tailscale-only, no public access).

## Project goals

Mobile-responsive entry point to everything on the box, auto-discovered from filesystem (PARA + nginx) with a thin override layer for labels/icons/ordering, plus a live chat panel to drive Claude Code on the server.

## Stack

- **Backend:** FastAPI, uvicorn, PyYAML — Python 3.12, uv-managed
- **Frontend:** CDN React 18 + Babel-standalone (no build step), JSX modules in `static/`. `marked` + `DOMPurify` via CDN for markdown rendering.
- **Deploy:** systemd service rendered from `deploy/orbit.service.template` by `scripts/install.sh`, port 8766, behind nginx at `/`. `BASE_PATH=""` for root deployment. Zero-downtime blue/green is in `deploy/advanced/`.

## Subpath / root deployment

Default deploy: `BASE_PATH=""` → app at root. Subpath-ready via `request.scope.root_path`, `url_for` everywhere on the backend, and `window.HUB_BASE_PATH` on the frontend — could move under e.g. `/hub` without code changes.

## Conventions

- `url_for` for ALL backend-rendered links (the bootstrap template still uses it for static asset URLs)
- `config/override.yaml` is **gitignored** — examples in `config/override.yaml.example`
- No per-request DB; in-memory caches with TTL (discovery cache: 30s)
- React JSX modules publish their components/hooks to `window` so sibling JSX files can pick them up (no bundler, no imports)

## Orchestrator panel (live)

- Chat with Claude Code running on this server, scoped to `~/`. Default surface is the in-browser ttyd **terminal** (tmux-backed interactive `claude`); the chat transcript is a plain-markdown mirror.
- Backend spawns `claude` (interactive, tmux) or `claude -p` (programmatic) per turn; native sessions own conversational context (`~/.claude/projects/-home-<user>/<uuid>.jsonl`)
- SSE streams the assistant response token-stream into the React panel
- Storage is minimal: the JSONL is the single source of truth; sidecar at `~/.orchestrator/sessions_meta.json` only tracks archive flags / title overrides — no SQLite
- Routes mounted by `orchestrator.register_routes(app)` from `app.create_app()`; `orchestrator_prompts.ensure_prompts()` runs once at registration
- The header's **Issues** + **artifact-gallery** buttons open `window.SessionOverlayModal` as modals OVER the live session (X / overlay-click / Escape / Back all close), never a view swap or a route away — the ttyd attach stays mounted. Openness is ROUTE state (`/chat/<sid>/gallery|issues`, parsed by `chat-route.js`), never a `useState`, so Back closes and a deep link opens; open pushes a history entry stamped `{hubOverlay:true}`, close consumes it with `history.back()` (or `replace`s when the entry isn't ours). Ownership rides on **`history.state`, not a ref** — a ref dies on reload and isn't restored by a Back→Forward, and the replace fallback then leaves two adjacent identical URLs so the next Back is a visible no-op. For the same reason `onSelectSession` carries the overlay through its URL sync (`HubChatRoute.overlayToCarry`): that replace also runs on the cold-load `hub:open-session` replay, and dropping the segment there killed every deep link. `_writeLastPath` strips the overlay so the PWA reopens the session, not a modal with no entry behind it. Escape peels ONE layer via `overlay-stack.js` — `Modal` gained an opt-in `closeOnEscape` (default off; ~30 existing call sites unaffected), and a modal rendered inside a hidden subtree must pass it as `false` (`OrchestratorView` stays mounted under `display:none`, so its artifact viewer gates on `isActive`). `closeOnEscape` also **takes and keeps DOM focus** (`tabIndex={-1}` on the card + a bounded `focusout` pull-back): the Escape listener is bound to the parent `window`, so while the ttyd **`<iframe>`** holds focus every keypress is delivered inside the iframe and Escape is simply dead. Taking focus once is not enough — ttyd focuses its terminal when the socket attaches, which on a deep link lands *after* the modal opened (measured: card focused at t≈12.4 s, stolen at t≈13.4 s). The pull-back is capped at 10 re-asserts so it can never turn into a focus war; if it gives up, Escape degrades and X / backdrop / Back still close. Focus returns to whatever held it when the modal closes, so the terminal is typeable again immediately. ⚠ `Modal`'s box uses **`.fade-in-transient`, not `.fade-in`**: `.fade-in`'s `both` fill leaves a permanent identity `transform`, which makes the box a containing block for `position:fixed` descendants — a nested dialog's backdrop then covers only the card, and a click on the visible scrim closes the HOST (losing an unsaved issue draft). The `viewMode === 'gallery'` view mode is **gone**.
- **⌘I / ⌘G toggle** the two overlays (`openOverlay` already closes when the same kind is open, so one binding does both directions, and the other key swaps in place). They ride the existing `_forwardAppShortcuts` bridge in `orchestrator-terminal-preview.jsx` — without it a shortcut is dead exactly when you'd press it, because the focused ttyd `<iframe>` eats the keydown before the parent window sees it. **⌘ only, never ctrl**, and they live in a separate `_FWD_META_ONLY_KEYS` set for that reason: forwarding *swallows* the combo, and in a terminal `Ctrl+I` **is** Tab (0x09) and `Ctrl+G` **is** BEL (0x07), so binding ctrl would break tab-completion in the pane. Linux/Windows reach them via Super, which is also `metaKey`. When the shortcut can't act (Issues on a global/resource agent, gallery with no session) it returns *without* `preventDefault`, leaving ⌘G as the browser's "find again" instead of a key that does nothing.
- **Keep-alive is surfaced at AGENT level, not just per session** (`orchestrator-agent-tabs.jsx`): a tab whose pool slots include a `persistent` one carries the same `pin-fill` glyph the session row uses, and its `title` counts them. It decides whether "Zamknij agenta" works at all (`planAgentClose` spares keep-alive), so hiding it meant the only way to discover the state was to open the context menu and find the action greyed out. ⚠ `_MenuItem` renders a disabled row's `hint` as **visible text, never `title`** — a `disabled` button fires no mouse events, so its native tooltip can never appear, which is exactly how "nie mogę zamknąć agenta" ended up with no stated reason. The hint is also actionable ("odepnij, żeby zamknąć agenta"), not just diagnostic.
- The terminal's **"Odśwież render sesji"** button (`_TermReloadButton`) renders on **both** breakpoints now — mobile keeps the bare top-right corner, desktop takes the 96/86 slot. It reconnects the ttyd client in place; a desktop page refresh would remount every session view to fix one pane's redraw. **The two ladders are ordered so the shared trio reads the same left-to-right on both** — desktop outward from the corner is fs 22/12 → select 60/50 → reload 96/86 → speak 132/122 → mic 168/158, mobile is reload 14 → speak 50 → mic 86 → last-msg 122, and both render as mic → speaker → reload. Reload first shipped in the outermost desktop slot, which put it on the opposite end from mobile; if you add a button here, place it by the rendered order, not by the next free number.

#### Issues overlay — width, search, send-to-agent

- **No horizontal scroll** is a `_ghPanelContainer` fix, not a width fix: the two-column grid used a bare `1fr 1fr`, whose implicit `min-width:auto` floors each track at its item's MIN-CONTENT, so one wide child (code block, markdown table, bare URL) inflated its own track — measured 691+956 px inside a 1098 px modal, i.e. 587 px of sideways scroll on the Modal body while the Card clipped it. `minmax(0, 1fr)` (+ `minWidth:0` on the Cards) fixes both render sites at once (the modal AND library-detail's Issues tab) and the PR panel with them. Widening alone never reached zero at any measured width. `.md-render`/`.gh-md` gained the matching containment in `tokens.css` — `.gh-md` (rendered issue COMMENTS) had no rule at all, so its `<pre>` could not even scroll; tables are `display:block; overflow-x:auto` and bodies `overflow-wrap:anywhere` (`anywhere`, not `break-word`, because only it lowers min-content).
- `_SOV_WIDTH.issues` is `'min(1700px, 96vw)'` — `Modal` puts a string straight into `style.width`. That is ERGONOMICS only (818 px columns on an 1800 px screen, so the list table's 689 px fits instead of scrolling behind its invisible `.scroll-hide` scrollbar). The panel's own `_ghUseCompact(880)` still keys on `window.innerWidth` and so still picks the LAYOUT (two columns vs one + fullscreen detail) from the wrong box; 880–1140 px viewports therefore get two narrowish columns. That is cosmetic now, because everything that depends on how much room the TABLE has asks the table:
  - **`_ghUseElementWidth()`** (ResizeObserver + `useLayoutEffect`, so the first measurement lands before paint) measures the list table's own wrapper, and **`_ghIssueCols(width)`** spends it: Author is dropped below 700 px, Labels below 620 px. Keying this on `window.innerWidth` was a real defect — at a 1000 px window the table is 446 px inside the modal, the viewport said "not compact", and the elastic title collapsed to 96 px (58 px at vw=920, ~5 characters) while Labels/Author kept full max-content and 10–20 px of them hid behind the invisible `.scroll-hide` scrollbar. The measuring div is the root of EVERY branch (loading/error/empty included) so a state-filter flip can't unmount it and flicker the column set.
  - The title cell is the only column that can yield (`maxWidth:0`), which also makes it the only one that can LOSE — so it asks for `width:100%` and every other cell for `width:1%` + nowrap (the standard one-elastic-column table idiom). A declared `55%` was a ceiling as well as a claim: it left 108 px of slack padding out `#` (54→92 px) and Updated (99→169 px). There is deliberately **no `minWidth` floor** on the title — a floor just pushes the metadata back off-edge behind the hidden scrollbar, which is the failure this replaced. Measured after: title 466/383/427/293/233 px at vw 1920/1440/1280/1000/880 with zero hidden scroll at any width, vs a flat 344 px + up to 291 px hidden before the feature and 307/230/96/58 px during it. The ellipsized title carries a `title=` attribute so the full text is still hoverable.
  - ⚠ `_GhPRTable` was left alone: it still hard-clamps its title at 320 px and still hides 228–368 px of Branch/Author/Updated behind the invisible scrollbar at ≤1280 px. Same recipe applies (`_ghTdNum`/`_ghTdTight`/`_ghTdTitle` + a column budget) if it ever matters.
- **Search** (`static/issue-search.js`) filters the ≤50 rows already fetched — client-side, undebounced, the house idiom. `body` now rides along on `_ISSUE_LIST_FIELDS`, capped at `_ISSUE_LIST_BODY_CAP` (20 000 chars) so a pathological repo can't turn every panel mount into megabytes; measured here 22 KB → 184 KB raw / 4 KB → 69 KB gzipped for 18 open issues. `#14` and `14` are the same ask and the exact number ranks first; folding is plain `toLowerCase` (NFD stripping is half-broken for Polish — it folds ó but not ł). **The truncation is SILENT** — `_clip_issue_body` appends nothing and reports the cut out of band on `body_truncated`, because on the list `body` exists ONLY as a haystack: a `…(obcięte)` marker made an ordinary Polish word match exactly the three longest issues, with nothing on screen to explain it. The result-count chip is gated on `!ctl.loading` for the same "the count must agree with the table" reason — `reload()` never clears `items`, so an Open→Closed flip otherwise showed the previous state's count for the ~0.8 s of the gh round trip. `tests/test_issues_feature.py` guards the field list and the clip (the Python half has no other coverage; dropping `body` degrades search silently).
- **"Rozwiąż" / "Dopracuj"** (`static/issue-agent-prompt.js`) reuse the artifact-reference pathway wholesale: `LibraryIssueList` gets a capability prop `onSendToSession(text)` that ONLY `SessionOverlayModal` passes, so library-detail's Issues tab renders no buttons and cannot paste into an unseen session. The event detail now carries `{text, sessionId}` and `referenceArtifact` prefers it over `state.activeId` (which lags a frame after a session switch) and toasts instead of dying silently when there is no target. Prompts are ONE LINE each by contract — 4+ lines collapse into claude's opaque `[Pasted text #N +M lines]` chip — and point at `gh issue view <n> --comments` rather than inlining a body that /term/paste caps at 8192 chars. The one-word labels are explained by `title` + `ariaLabel`, which required teaching **`Button` (components.jsx) to forward them at all**: its destructure is closed (no rest spread), so every `title=` on a Button in this repo — including the pre-existing one on "Make task" — had been dropped by React before reaching the DOM.

### Detached sessions (survive `systemctl restart`)

The dashboard is a systemd **system** service (`KillMode=control-group`), so a tmux server forked from it inherits the service cgroup and a restart SIGKILLs every `claude` REPL. The `tmux_detached_sessions` flag (default **True**, in `orchestrator_settings`) fixes this end-to-end — four conspirators had to change together:

1. **Cgroup escape** — `SubprocessTmuxRunner.spawn` wraps the tmux server launch in `systemd-run --user --scope -- …` (`orchestrator_tmux._user_scope_prefix`), so the server lands in `/user.slice/…` (a sibling of the service). Needs the per-user bus: `XDG_RUNTIME_DIR=/run/user/1000` (set in the unit) + **linger** (`loginctl enable-linger <user>`). Falls back to a legacy in-cgroup spawn if `systemd-run`/the bus is unavailable (session still *starts*, just won't survive). tmux's native systemd integration additionally auto-scopes each pane once the bus is reachable.
2. **No teardown on shutdown** — the lifespan calls `pool.shutdown(kill_sessions=False)` (`app.py`) so a graceful stop drops in-memory pool state but leaves the REPLs running.
3. **Re-attach** — `TmuxPool.acquire` adopts an already-live `hd-<id>` session instead of `new-session` (which errors "duplicate session").
4. **Orphan sweep spares survivors** — `recover_orphans` preserves `hd-*` sessions (still sweeps non-`hd-` junk like the `main` session `~/.tmux.conf` auto-creates).

The unit also sets `PrivateTmp=true`, so the default tmux socket (`/tmp/tmux-1000/hd-orch`) lives in a per-start ephemeral `/tmp` that's destroyed on restart — the survivor would become invisible. `ensure_tmux_socket_dir()` (called at lifespan start, before any tmux call) pins `TMUX_TMPDIR` to `~/.orchestrator/tmux` (shared host fs via `ReadWritePaths`, persistent, pre-created so tmux doesn't fall back to `/tmp`), so spawn + every `_tmux` client + ttyd resolve the same restart-stable socket.

Rollback L1: flip the flag off (Settings → Terminal or `settings.json`) → pre-feature behavior. Known trade-off: survivors that are never re-opened linger until manually killed (the idle evictor only reaps *tracked* slots).

### Per-session git worktrees (opt-in)

A session can run its claude REPL inside its own git worktree, using claude-cli's built-in `--worktree <name>` (worktree at `<repo-toplevel>/.claude/worktrees/<name>`, branch `worktree-<name>`, based on `origin/<default>` when a remote exists). Ticked per session in the new-session modal; blank name ⇒ the server generates one (`bold-oak-vgrj` style). Flag: `worktree_sessions_enabled` in `orchestrator_settings` (default **True**), Settings → Serwer. Enabled-by-default is safe by construction: the checkbox is unticked, and it self-disables for any cwd that isn't a git repo — nothing changes until you opt in per session.

**The invariant:** `meta.cwd` **stays the agent dir**; the worktree lives in separate `worktree_name` / `worktree_path` / `worktree_repo_root` sidecar fields. Rewriting `cwd` would break the `?cwd=` session filter, the frontend's agent grouping, `_lib_id_from_cwd` (it would invent a phantom agent), `artifacts_dir()`, `prompts_for_session` and the skills farm — all at once. `orchestrator_worktree.resolve_spawn_target(sidecar, sid)` is the single decision point, returning `(cwd, worktree_flag, resume, transcript_cwd)` together so they cannot drift.

Behaviour pinned by a real probe against claude-cli 2.1.220 (not by reading docs):

- **The transcript is written to the WORKTREE's project slug**, regardless of which dir claude was launched from. `TmuxClaudeRunner` therefore takes `transcript_cwd` separately from `cwd`; anchoring the tail on the launch dir makes a turn that *succeeded* die at `TURN_TAIL_TIMEOUT_S` (600 s) with "timed out waiting for JSONL flush".
- **`--resume` is forgiving about the launch dir** — resuming from the repo root works and claude re-enters the worktree itself. So `cwd` is an ergonomics choice (we spawn *inside* the worktree so the pane's `pwd` is honest), not a correctness one.
- `--worktree` is emitted on the **cold spawn only** — re-passing it on an existing worktree can `git reset --hard` the branch back to the base ref. It goes in as ONE token (`--worktree=<name>`) so an odd name never sits at an argv boundary. `--tmux` joins `--bare`/`-p`/`--print` on `build_spawn_cmd`'s refuse-list (it forks a nested tmux on the *default* socket).
- **claude's `git worktree lock` survives process death.** A plain `git worktree remove` after a session ends always fails; `remove_worktree` waits briefly for the pid to actually exit (it has not reaped yet when the slot is released), then unlocks — but only for claude's own marker with a dead pid, never a live or foreign lock.
- A **missing `origin` is fine** (falls back to local HEAD); a **non-repo cwd is not** (claude exits 1), which is why preflight's is-repo gate matters: most `~/Areas/*` are not repos, and Global (`$HOME`) never is. Those degrade to a greyed checkbox — the modal still creates a normal session.

Deleting a session **keeps** its worktree; the delete confirm has an opt-in "usuń też worktree" checkbox → `DELETE …?worktree=remove`, never `--force`, so a dirty tree refuses and is reported back as `worktree_removed:false` + git's reason. The branch is always left alone.

**Worktree env:** a fresh checkout has no `.venv` / `config/override.yaml`. This repo ships `.worktreeinclude` (committed — copies the gitignored config) and `.claude/settings.json` with `worktree.symlinkDirectories: [".venv","node_modules"]`. ⚠ `.gitignore` ignores all of `.claude/`, so the symlink half is **per-machine** and must be recreated on a fresh clone. Preflight warns when a repo has `.env`/`.venv`/`node_modules` but neither mitigation.

Rollback L1: flag off → the checkbox never renders and POST rejects a `worktree` payload; **existing worktree sessions keep working** (the resolver deliberately ignores the flag — routing them back to the repo root would resume from the wrong slug). Chip/badge gate on `worktree_name`, not the flag, so nothing gets mislabelled. L2: drop the modal's worktree block + the settings row. L3: delete `orchestrator_worktree.py`, `static/worktree-name.js`, `static/orchestrator-new-session-modal.jsx`, the routes, the flag and the three sidecar fields.

## Replies & artifacts (envelope removed)

The `{"blocks":[…]}` JSON response envelope was **removed** (the ttyd terminal made it unusable — Claude writes prose, not JSON). Replies are now **plain GitHub-flavored Markdown**; both runners finalize the assistant turn as an `assistant_message` markdown block. Choices use the native **AskUserQuestion** tool. Old transcripts stay readable via a self-contained shim in `orchestrator_jsonl._try_parse_envelope` (recognises legacy envelope JSONL, extracts markdown/code/image). System prompts are `v14`; per-agent baselines `v2` (`agent_prompts._seed_or_migrate` backs up + rewrites stale copies, never touches `identity.md`/`custom.md`).

Rich media is a first-class **artifact** instead of an inline block:

- Claude runs the `artifact` CLI skill → writes `<id>.<ext>` + `<id>.json` manifest into the agent's `<cwd>/.artifacts/` (committable to the project repo; **global** agent → `~/.orchestrator/artifacts/global/`). Types: image/audio/video/youtube/chart/map/html/file/**doc** (chart/map/youtube specs inline in the manifest; `doc` = markdown/text handed over directly, written to `<id>.md`, capped at 1 MB — the "read it, don't download it" type). The skill **ships in the repo** at `skills/artifacts/` and is installed into the registry on boot by `bundled_skills.seed_bundled_skills()` (like `generate-image`/`notify`), so the CLI lives at `~/.orchestrator/skills-registry/artifacts/scripts/artifacts_cli.py` — no manual rsync.
- `orchestrator_artifacts.py` is the dashboard-side reader/mutator + dir resolver (keyed on lib_id, traversal-guarded). The `/file` route serves with a **safe-mime allowlist + nosniff** so an agent-written manifest can't pick an executable Content-Type on the app origin — which also means it can only ever *download* a pdf/csv/log.
- **`/preview` is the read-in-place counterpart** (`preview_kind()` decides): text-family payloads come back as `text/plain` (never `text/html` — same-origin XSS), truncated to `?limit=` with `X-Artifact-Truncated`/`X-Artifact-Size`; pdfs come back as `application/pdf` under the same `Content-Security-Policy: sandbox` opaque-origin pin `/view` uses; anything else 415s so the UI falls back to the download row. `/thumb` additionally rasterises **page 1 of a pdf** via poppler (`pdftoppm`), 404-ing to the icon when poppler or the file is unusable. Downloads use the agent's original filename from `extra.filename` (basename'd + control-char stripped before it reaches a header).
- **Panel artifact vs claude.ai artifact**: the native `Artifact` tool publishes to claude.ai and is invisible in this dashboard, so agents reaching for it silently deliver nothing. `skills/artifacts/scripts/native_artifact_guard.py` is a **PreToolUse hook** (registered in `~/.claude/settings.json` with `matcher: "Artifact"`) that blocks publishing actions until someone runs `native_artifact_guard.py allow` (30-min window in `~/.orchestrator/native-artifact-optin.json`); read-only actions (list/comments/…) always pass. The refusal text tells the agent to use the panel CLI, or to ASK the user first. Headless `claude -p` sessions don't even get the tool — this is an interactive-session problem only.
- `orchestrator_events.py` `SessionEventHub` is a process-lifetime per-session SSE channel **independent of the turn runner** (which reaps ~60s after a turn) — `artifact create` pushes a toast, `artifact open <id>` pushes a modal, even between turns. The CLI POSTs `/api/orchestrator/artifacts/notify` (token-gated via `~/.orchestrator/artifact_token`); the browser holds a persistent `GET /sessions/{id}/events` EventSource.
- Frontend: `static/orchestrator-artifacts.jsx` renders the gallery (per-session in the chat panel, per-agent in the Agent panel) + viewer modal, **reusing** the widget renderers in `orchestrator-widgets.jsx`. `_artPreviewKind()` mirrors the backend's `preview_kind()` and routes a `file` three ways — pdf `<embed>`, scrollable text + **Kopiuj**, or the plain download row; `doc` renders as markdown (marked + DOMPurify, the `file-preview.jsx` path) with a source toggle. Tiles show a pdf page-1 thumb or a text snippet instead of a generic icon. The runner injects `HD_SESSION_ID`/`HD_LIB_ID`/`HD_NOTIFY_URL`/token-file so the CLI auto-discovers its session.

## Settings page (tabbed)

The Settings view is split from one flat 1885-line file into focused modules (loaded in this order, all before `orchestrator-blocks.jsx`):

- `settings-primitives.jsx` — **the contract**. Publishes `window.useSettings` (per-device localStorage hook — external consumers like `orchestrator-unread`/`-conversation` read it off `window`), `useServerSettings` (GET/PATCH `/api/orchestrator/settings`, optimistic-with-revert, **module-level cache** so the Serwer↔Terminal tab switch doesn't refetch/flash), and the `window.HubSettings` UI atoms: `SettingCard`/`SettingRow`/`ToggleRow`/`FieldRow`/`SettingGroup`/`Toggle`(44px tap)/`Segmented`(wraps)/`SettingSelect`/`NumberField`/`ScopeChip`/`AdvancedDisclosure`/`StatusBanner`.
- `settings-notifications.jsx` / `-voice.jsx` / `-server.jsx` / `-terminal.jsx` — per-tab bodies (`window.Settings{Notifications,Voice,Server,Terminal}`). `-shortcuts-editor.jsx` is the shortcut layout editor, opened as a drawer from the Terminal tab.
- `settings-view.jsx` — the shell: 5 tabs (**Powiadomienia / Głos / Czat / Serwer / Terminal**), owns the single `useSettings` instance and passes `{settings,updateSettings}` to device-scoped tabs; server tabs call `useServerSettings()` themselves. Tabs are **URL-synced** (`/settings/<tab>` via `useRouter().replace` — `parseRoute` keeps `section:'settings'`, so no router/app.jsx change) → deep-linkable + restored on PWA reopen.

Conventions: every group carries a **`ScopeChip`** — `device` (this device / localStorage), `server` (whole server / `~/.orchestrator/settings.json`), or `secrets` (`~/.env`). Niche/rollback knobs (the 5 `*_runner_mode` levers, `pool_prewarm_on_start`, `terminal_instant_attach`, `ttyd_port_min/max`) live behind an `AdvancedDisclosure`; **no settings were deleted** — the "legacy" `programmatic` runner modes are deliberate billing-rollback levers. RWD: the shell root carries `className="settings-root"`; tokens.css bumps form controls to 16px **inside `.settings-root` only** on `≤960px` (kills iOS auto-zoom without touching the rest of the app).

Two backend touches support the redesign: (1) **`GET`/`PUT /api/notify/mutes`** (in `notify_routes.py`) read/write `NOTIFY_DISABLE_TOPICS` **without captcha** (topic names, not a credential) and update `os.environ` live; (2) `secrets_routes._put_env`/`_delete_env` now **sync `os.environ` for the `global` scope** so an inline-written `~/.env` secret (e.g. the Telegram token entered in Settings) takes effect without a process restart.

## Powiadomienia: jeden temat = jeden wątek Telegrama

`notify.notify(topic=…)` used to let `topic` pick only an emoji + hashtag; every alert landed in the single `TELEGRAM_CHAT_ID`. `notify_topics.py` makes the topic pick a **destination**: a `message_thread_id` inside one forum-enabled supergroup, so the phone shows one chat that opens into per-topic threads with their own unread counts and mute switches.

- **`resolve(topic)` is the whole contract** and the fallback ladder is deliberate: no `group_chat_id` ⇒ `(TELEGRAM_CHAT_ID, None)`, byte-identical to the pre-feature payload (the file is opt-in and arrives empty — an install that never opens Settings notices nothing, and **blanking the group is the L1 rollback**); group + mapped topic ⇒ `(group, thread_id)`; group + **unmapped** topic ⇒ `(group, None)`, i.e. General — an unrouted alert delivered to the wrong thread is recoverable, one that is dropped is not, and any caller may invent a topic string. A per-topic `chat_id` outranks the group (hybrid escape hatch, hand-edit only). A `thread_id` **without** a group is discarded rather than applied to the legacy 1:1 chat, where every send would 400.
- **A deleted forum topic must not swallow the alert.** `_is_thread_missing()` spots Telegram's `message thread not found` / `TOPIC_DELETED`, and `notify()` retries **once** without the thread, then reports `thread_fallback:true` in the envelope (the Settings test button says "trafiło do General", not a bare "wysłano" — a stale mapping otherwise hides until you notice messages piling up). Only that one error retries; a malformed body still fails once.
- **The Bot API cannot list forum topics** — a bot only learns a `message_thread_id` from an update it received in that thread. Hence two setup paths: `POST /api/notify/routes/create-topics` (the bot creates them itself; needs admin + *Manage Topics*) or `POST …/discover`, which mines `getUpdates` for threads the bot has seen (Telegram keeps those ~24 h, so creation is the preferred path). Create reports **per-topic** outcomes and saves whatever succeeded — partial success is the norm, and re-running fills the gaps.
- Storage: `~/.orchestrator/notify_routes.json` (schema v1), size-gated before `json.load`, re-sanitized on read *and* write (the file is hand-editable and feeds an outbound API call, so a bad chat id fails here rather than as an opaque 400 on the cron hot path), cached until mtime moves. Config is not a credential (a group id is useless without the bot token), so `GET`/`PUT /api/notify/routes` skip the captcha exactly like the mutes endpoints do.
- UI: `_RoutingGroup` in `settings-notifications.jsx` (Settings → Powiadomienia, under the Telegram card) — group id + Wykryj/Utwórz wątki + a per-topic row with a thread badge and its own Test button.

## Terminal shortcut manager (mobile soft-keyboard)

The mobile soft-keyboard toolbar (`_MobileSoftKeyboard` in `static/orchestrator-terminal-preview.jsx`) sends keys to the live xterm.js terminal **client-side** (synthetic KeyboardEvents into xterm, raw PTY bytes for tmux chords, paste, or special actions) — there is **no managed `~/.tmux.conf`**, so "applying" a change is just the React toolbar re-reading config; no session restart.

A **full views+buttons management panel** in Settings (`SettingsShortcutsEditor` in `settings-shortcuts-editor.jsx`, opened as a drawer from the Terminal tab's `settings-terminal.jsx`) lets the user define the whole layout: add/remove/edit/hide/reorder **views**, and per view add/remove/edit/hide/reorder/**pin** buttons (row actions collapse into a kebab menu on narrow screens). Adding a button picks a **kind** (`_ButtonEditModal`): `send-key` (capture or build), `send-raw` (a string with escapes `\n` / `\x1b` ESC / `\x00` tmux C-Space prefix — live hex preview), `paste-text` (+optional Enter), `slash-command`, or `special` (microphone / upload / clipboard-paste / session-switcher). A 6th kind `modifier` (sticky Ctrl/Alt/Cmd) is schema-only — seeded, not in the Add picker. **Structural anchors** — the view cycler + the red Esc + Tab — are always rendered, never in the layout, so they can't be deleted/bricked. Built-in **⇤ Ctrl+A** / **⇥ Ctrl+E** line-nav buttons ship in the Nawigacja seed.

- **Single source of truth = backend `DEFAULT_LAYOUT`** (Python, in `orchestrator_terminal_shortcuts.py`). `GET` always returns a complete renderable layout (seeded if no file). The frontend keeps the literal `_NAV_KEYS`/`_SPECIAL_KEYS`/`_ACTION_KEYS` arrays ONLY as the flag-off render fallback (a drift test cross-checks them against the seed). Do NOT add a cross-module frontend seed — `orchestrator-shortcuts.jsx` loads before `orchestrator-terminal-preview.jsx`.
- **Flag + rollback (opt-in):** `terminal_shortcuts_enabled` in `orchestrator_settings.py` (default **False**). OFF → the toolbar renders the static default arrays (via the same unified `renderButton`) and the manager hides (level-1 rollback). Level 2: drop the manager UI + the `applyLayout` branch in the toolbar. Level 3: delete `orchestrator_terminal_shortcuts.py`, the routes, the flag, `static/orchestrator-shortcuts.jsx`, and `~/.orchestrator/terminal_shortcuts.json`.
- **Storage (schema v1):** `{version:1, layout:{views:[{id,label,icon,hidden?,buttons:[{id,kind,label,hint?,icon?,pinned?,hidden?,payload}]}]}}` at `~/.orchestrator/terminal_shortcuts.json` (server-side → follows the user across devices). Array order == render order; pinned render first. `GET`/`PUT` (full replace) + `POST .../reset` (reseed); the GET also returns the flag as `enabled`. The store size-gates before `json.load`, re-sanitizes on read/write (caps, per-kind validation, unknown kinds dropped, `send-raw` validated by decoding — control bytes allowed, decoded length capped, malformed escapes drop the button), and `get_layout()` deep-copies. The old sparse-override file is discarded + reseeded.
- **Wiring:** `static/orchestrator-shortcuts.jsx` publishes `window.HubShortcuts` (cached fetch/save store, `useConfig()` hook, `applyLayout`, `decodeEscapes`, `kindLabel`/`labelForButton`/`labelForDescriptor` + key helpers) — loaded before both consumers. The toolbar's `renderButton`/`dispatchButton` switch on `kind` (reusing `_sendKeyToIframe`/`_sendRawToTerminal`/`_pasteToTerminal`); the flag-off path maps the legacy arrays via `_legacyToButton` into the SAME renderer. Saves dispatch `hub:terminal-shortcuts-change` so an open toolbar updates instantly.

## Geolokalizacja urządzenia (round-trip do przeglądarki)

An agent asks the USER'S browser for `navigator.geolocation` and blocks until it answers ("gdzie jestem?", "co jest najbliżej?"). It rides the **existing** per-session SSE hub — two new events (`geo_request` / `geo_cancelled`) on `orchestrator_events.SessionEventHub`, no second EventSource, no lifespan wiring, and the flag is checked *inside* each route, so toggling needs no restart. `orchestrator_geo.py` is the FastAPI-free core (`_PENDING`, `create_request` / `submit_answer` / `await_fix_guarded` / `cancel` / `cached_payload`); the `STATUSES` table lives next door in `orchestrator_geo_statuses.py` and is re-exported, so `orchestrator_geo` stays the ONE import site; `orchestrator_geo_coords` rebuilds untrusted coords key-by-key (never merges a browser dict) and owns `degrade_fix`; `geo_routes.register_geo_routes(app)` mounts the 10 `/api/orchestrator/geo/*` routes. Agent→server is gated on `X-Geo-Token` (= `~/.orchestrator/artifact_token`, the a2a idiom); browser→server is un-gated — the `request_id` is the capability. **HTTPS only:** `!window.isSecureContext` auto-answers `insecure_context` before any `navigator` call, so `http://100.64.0.1:8766` degrades and only `https://your-dashboard.example/` can take a fix.

- **Single source of truth = `STATUSES`** (Python) — 18 rows of `reason` / `retryable` / PL `message` / PL `hint`; `static/geo-consent.js` holds a verbatim copy for the browser half, drift-guarded from both sides (`tests/geo-consent.test.js`, run by hand — CI is pytest-only). `retryable:false` ⇒ the agent must NOT re-ask this turn. `/wait` carries `terminal:bool`; re-poll iff `terminal is false`.
- **Consent defaults to `auto`** (device setting `geoConsentMode`, Settings → Serwer): no in-app modal, the browser's own permission sheet is the only blocking gate — but a **mandatory non-blocking toast** fires on every fix (agent name + a `Wyłącz` link). `ask` restores the ConfirmModal + the 15-min snooze. The per-device `geoOptOut` outranks both modes and answers `device_opt_out`.
- **Storage is in-memory only** — one global `_last_fix` (TTL 900 s) + the geocode caches, nothing on disk, no state file to migrate; `POST /geo/forget` clears both and lat/lon is never logged. **But the fix does land in the session transcript** (the JSONL), and `geo …  --map` writes an artifact manifest **containing the coordinates** into `<cwd>/.artifacts/` that `forget` does NOT touch — so "nothing is persisted" is true only of the dashboard's own storage. Say so to the user, don't oversell it.
- **The cache is measurement-aged and accuracy-aware.** `getCurrentPosition` may answer from the platform's own cache (its `maximumAge` mirrors `--max-age`), so `_last_fix` is stamped with `ts_ms`, not with receipt — otherwise a 5-minute-old reading is re-served as "1 s ago" for another 15 minutes. `cached_payload()` is the single serving path: a stored `fine` fix is re-rounded for a `coarse` ask (`degrade_fix`), a stored `coarse` fix can never answer a `fine` one (reads as a miss → re-measure). `GET /geo/last` serves it read-only, as stored — `geo last` must never register an ask, or an empty cache would fire a real permission prompt.
- **Delivery + timeout ladder** — targets the asking session if a browser is attached, else fans out to ≤8 live sessions, else fast-fails `no_browser` in <100 ms with no pending entry. A refusal is terminal only once every target answered AND `expected_n` answers arrived (`_expected_answerers` counts live EventSources, not targets — two tabs share one session id, and the laptop's `unavailable` must not throw away the phone's fix). Must not drift: `getCurrentPosition` 20 s < `/wait` window 45 s (max 60) < request TTL 180 s.
- **Geocoding is separately flagged** (`geolocation_geocode_enabled`, default **True**): `/geo/reverse` + `/geo/nearby` send the coordinates OFF THE BOX to public OSM servers (Nominatim, Overpass) — hard 1 req/s + 1 req/2 s gates, 8 s timeout, one attempt, own User-Agent, in-memory TTL caches. Off ⇒ a **200** with `status:"geocode_disabled"` (not a 403), so the CLI degrades to raw lat/lon.
- **Agent surface** = the bundled `skills/geo/` CLI (`geo status|where|nearby|last|forget`), seeded into the registry by `seed_bundled_skills()` like `artifacts`, plus `geolocate` / `geo_nearby` in dashboard-mcp.
- **Flag + rollback:** `geolocation_enabled` in `orchestrator_settings` (default **True**, Settings → Serwer). L1: flag off ⇒ every agent-facing route 403s with an actionable detail, `useGeolocationRequests` goes inert (no modal can ever appear), the browser `answer`/`pending` routes refuse in a typed body (a stale tab must stop, not retry — and its late fix must not become the cache), and `geo_routes.on_feature_disabled()` — called from the settings PATCH — aborts the asks already on screen and forgets every coordinate. The per-device opt-out (toast link + Settings toggle) also POSTs `/geo/forget` for the same reason. L2: drop `static/orchestrator-geolocation.jsx` + its script tags, the two `addEventListener`s in `orchestrator-artifacts.jsx`, the `orchestrator.jsx` call site and both settings blocks — backend + skill keep working headlessly (everything resolves `expired`). L3: delete `orchestrator_geo*.py`, `orchestrator_geocode.py`, `geo_routes.py`, `static/geo-consent.js`, `skills/geo/`, the `register_geo_routes` call, both flags, `geoConsentMode`/`geoOptOut` and the two `SessionEventHub` accessors. **Nothing on disk to clean up.**

## Tasks tab (live)

GitHub-Issues backlog backed by a single Projects v2 board (config under `tasks:` in `config/override.yaml` — see `.example`). Disabled by default; flip `tasks.enabled: true` to mount routes + start the reminder loop.

- **Single source of truth:** GH. Items cached 30 s in memory, schema cached 5 min, both bust on writes. The sidecar at `~/.orchestrator/tasks.json` stores **reminder configs + delivery state only** — never duplicates issue data.
- **Auth:** reuses `library_github._gh_env()` / `_gh_auth_check()` (the existing `gh` CLI keyring). `project` scope is required (`gh auth refresh -s project` if missing).
- **PARA tagging:** issues live in per-area / per-project repos. Area / project encoded as labels (`area:<slug>`, `proj:<slug>`, `global`). The PATCH endpoint **refuses cross-repo moves** with HTTP 422 — close + recreate is the supported flow.
- **Reminders:** `tasks_reminders.scan_and_fire()` runs every 60 s via `cron_store` (job id `tasks-reminders`, command `python -m orbit tasks-reminders-tick`). Each reminder slot is stamped on first fire; restart-after-outage replays within `grace_window_hours` (default 6) and silently no-ops beyond that. Delivery goes through `notify.py` topic `tasks` (Telegram, "Open task" inline-keyboard button).
- **Skill parity:** a project-agnostic Claude skill lives at `~/.claude/skills/gh-tasks/` (CLI + importable `gh_tasks.py` + bootstrap script). The dashboard and the skill don't share code — only the GH project as the source of truth — so each can ship independently. Install on the Hetzner box with a manual rsync of the skill directory.
